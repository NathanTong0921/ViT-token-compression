# 潜在专用优势与训练目标：聚焦补强

本轮完成了 proposal H1 与 H3 之间的一项延伸：已有实验发现任务信息有用，却不总能超过强共享选择器，因此进一步检验潜在选择空间和训练目标的作用。设计在新结果产生前固定，见[协议](../../docs/conditioning-objective-followup.md)。全部结果仍来自开发划分，预留测试图片与测试类别组合未使用。

## 核心结果

保持教师、架构、初始化规则、训练数据流及更新数，比较 KL 与 Top-k boundary ranking 两个目标，分别训练条件化和图像版 selector。Pets／Flowers 的 49／98 token 设置各保留三个配对种子，共新增 24 个模型。

主指标是“更换目标后，条件化相对图像版的优势变化”，即 `(C−U)_rank − (C−U)_KL`。准确率单位为百分点；margin 为归一化几何间隔。

| 数据集／预算 | margin 交互效应 [调整区间] | 准确率交互效应 [调整区间，百分点] |
| --- | --- | --- |
| Pets 49 | +0.002812 [+0.001771, +0.003808] | +0.0066 [−0.3932, +0.3954] |
| Pets 98 | +0.000598 [−0.000338, +0.001550] | −0.1967 [−0.4753, +0.0631] |
| Flowers 49 | −0.000753 [−0.001816, +0.000349] | −0.3676 [−0.9805, +0.2207] |
| Flowers 98 | −0.000812 [−0.001569, −0.000051] | −0.4167 [−0.8578, 0.0000] |

区间使用 2,000 次配对图片 bootstrap；在每个数据集、每项主指标内对两个预算作调整，单项区间为 97.5%。先平均三个种子的逐例指标，再以图片为重采样单位；这不包括重新抽取训练种子或任务集合的总体不确定性。Flowers98 准确率上界的浮点残差按零解释。四个准确率交互的调整区间均包含零。

Pets49 的条件化减图像版 margin 从 KL 的 −0.000919 转为 ranking 的 +0.001893，三个种子的交互均为正；Flowers98 的 margin 优势从 +0.001363 降为 +0.000552，三个种子的交互均为负。更换训练目标改变了条件化相对收益，但没有构成跨设置一致的准确率改进。各臂绝对表现、种子结果及共同教师诊断见 [Pets](../pets-selector-objectives-v1/README.md) 和 [Flowers](../flowers-selector-objectives-v1/README.md)。

## 潜在空间与可实现收益

Pets49／98 的共同有限库允许任务分别选取 token，比为两个任务选同一集合的最大平均 margin 分别多 0.006182／0.006406。学习器实际差异分别为 −0.000797／+0.000511；这里按同图任务对及图片等权，和上表的任务／类均衡口径不同。离线选择知道标签与两个任务，不能当作可部署共享基线；有限库中的最优也不是所有集合中的全局最优。

排除学习器和教师选择、只使用 512 个随机 probe 后，潜在差距的留出图片增量 R² 为 +0.00455／−0.00064，两个调整区间均跨零。49-token 的调整后关联为正，但没有建立稳定的额外预测收益。分解提供了潜在空间与实现差距的量化；它本身是恒等式，不能单独证明原因。见[完整诊断](../pets-conditioning-gap-v1/README.md)。

## 研究解释

1. **训练目标是影响条件化收益的一个因素。** 固定训练方案下，Pets49 与 Flowers98 的 margin 交互有相反方向，限制了“换目标即可普遍改善”的解释。
2. **教师拟合与实际分类需要分别测量。** 所有 ranking 臂的绝对教师 Top-k 重叠率均低于 KL。Pets49 的条件化相对重叠率与实际 margin 同时反转；Flowers98 的相对重叠率几乎不变，实际 margin 优势却减小。单一重叠率不能充分解释观察结果。
3. **这项干预补充了可学习性分析。** 它表明，同一份任务信息在不同训练目标下会产生不同的相对收益；教师拟合和实际分类的共同记录帮助定位差异。优化尺度等实施细节保留在各数据集的内部诊断中。

对项目的推进是正面的：从描述条件化收益不稳定，推进到一次配对训练干预及外部复核。新增贡献主要在于解释训练目标如何影响任务信息的利用；原 KL 方法仍是后续最终确认的主方法。
