# 2026-10-27：ViT-L/14 定向验证与实际推理效率

## 问题与结论

按[预测前固定的方案](../vitl-and-latency-validation.md)，回答两项问题：H2 与条件化收益能否在另一 backbone 上重现，以及计入在线选择开销后是否真的更快。

**H2 在 L/14 的 Pets 和 Flowers 上均得到复核；条件化的分类收益仍依赖设置。** Flowers 准确率提高 0.1471 个百分点，Pets 平均分类间隔反而更低。实际速度方面，保留一半 patch 的条件化方法在 batch 32 得到约 1.25×（B/16）／1.29×（L/14）加速；batch 1 没有加速。延迟预检引出的完整验证集数值复查发现，批量形状会改变部分选集，主效应变化较小但并非全为零。

本轮完成 proposal 的跨模型验证、实测延迟、监督与训练成本部分，形成 [I10–I11](../research-insights.md)。官方测试图片及保留类别组合仍未用于训练或预测。

## 跨模型执行范围

冻结 OpenAI CLIP ViT-L/14，输入 224×224，block 12／24 后保留 128／256 patch 及 CLS。对应 B/16 的 block 6／12、98／196 patch 比例；没有搜索 L/14 最优预算。视觉宽度 1,024、输出维度 768，两种 selector 各 480,641 参数，从头训练而非迁移 B/16 selector 权重。

| 设置 | 训练／验证图片 | 训练／验证类别对 | 每臂更新 | 未见组合图片／任务样本 | 同图交换任务对 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Pets | 2,944／736 | 532／66 | 3,990 | 716／2,624 | 4,315 |
| Flowers102 | 1,020／1,020 | 612／204 | 3,978 | 1,020／4,080 | 6,120 |

每图使用 512 个固定预算 mask 生成 ridge 0.01 监督。三个配对种子 2041／2042／2043、hidden width 128、batch 128、原 KL 训练路线，采用最终步权重。每个数据集包含六个 selector 训练臂。所有训练／验证图片的 keep-all 特征与原始 CLIP 完全相同。

主分类指标按任务等权、任务内类别等权；训练种子先平均，再作 2,000 次图片聚类 bootstrap。L/14 每数据集只有一个预定预算，使用 95% 区间；B/16 图表保留 Pets 原三预算的 98.333% 区间和 Flowers 原两预算的 97.5% 区间。H2 在两个 L/14 数据集分别检验，联合复核标准为两个难度调整斜率的 95% 区间均为正；没有将该规则扩展为所有指标的全局错误率控制。

## 分类与 H2 结果

| 指标 | Pets L/14 | Flowers L/14 |
| --- | ---: | ---: |
| 条件化 − 图像版：准确率（百分点） | −0.0126 [−0.0763, +0.0392] | +0.1471 [+0.0245, +0.2859] |
| 条件化 − 图像版：分类间隔 | −0.000638 [−0.001006, −0.000270] | +0.000222 [−0.000163, +0.000603] |
| 正确描述 − 交换描述：分类间隔 | +0.000361 [+0.000272, +0.000455] | +0.001138 [+0.001003, +0.001272] |
| H2 难度调整斜率／10° | +0.000228 [+0.000137, +0.000323] | +0.000579 [+0.000389, +0.000771] |
| 图片固定效应斜率／10° | +0.000315 [+0.000213, +0.000415] | +0.000763 [+0.000565, +0.000958] |

表内均为 95% 区间；交换与 H2 按图片等权，和主分类指标的权重不同。每个训练种子的 H2 斜率方向也均为正。R² 区间重采样既定折外预测，未重复拟合所有重采样模型。

Pets 的 B/16 半预算正间隔优势没有在 L/14 复现，Flowers 的小幅准确率优势则得到复核。两个 backbone 同时改变 patch 大小、深度、宽度、文本表示和 selector 输入维度，不能从这个比较单独推断模型大小的作用。跨设置更稳定的发现是 H2 的额外关联和预测价值，而非条件化普遍优于共享模型。

详见 [Pets 结果](../../results/pets-vitl128-v1/README.md)、[Flowers 结果](../../results/flowers-vitl128-v1/README.md) 和[跨模型图表](../../results/vitl-and-latency-v1/cross_backbone_validation.png)。两份独立科学审计从原始预测复算主效应与图片区间、特征交换关系、H2 点估计和留出图片拟合；斜率 bootstrap 本身没有重复执行。

## 实际推理速度

正式计时在一张 RTX A6000（physical GPU 1）执行，覆盖七个设置：B/16 Pets 49／98／147、Flowers 49／98，以及 L/14 两数据集 128-token。比较完整模型、attention、图像版和条件化 selector，学习方法保留全部三个种子。

各数据集使用同一固定 128 图计时面板及预定有效未见任务，batch 1／32；每方法预热十次，五轮、每轮二十次，轮内方法顺序随机化。batch 1 的正式计时覆盖 100 张不同图片，batch 32 覆盖全部 128 张。准确率来自完整验证集，不使用计时面板准确率。

主计时从 GPU 上的预处理图片开始，到候选类别余弦得分结束，包含完整前缀、在线任务描述构造、selector、排序／索引、后缀与归一化。各方法缓存相同类别文本，不缓存图像前缀、不作请求重用、不填充批量。CPU 图片处理与输入传输单独测量，不把它们与异步 GPU 时间简单相加成服务耗时。

| 条件化设置 | batch 32 中位耗时（ms／批） | 同轮配对加速比中位数 |
| --- | ---: | ---: |
| Pets B/16，49 tokens | 16.992 | 1.473× |
| Pets B/16，98 tokens | 20.032 | 1.256× |
| Pets B/16，147 tokens | 23.242 | 1.080× |
| Flowers B/16，49 tokens | 17.066 | 1.473× |
| Flowers B/16，98 tokens | 20.037 | 1.255× |
| Pets L/14，128 tokens | 75.722 | 1.287× |
| Flowers L/14，128 tokens | 75.490 | 1.286× |

batch 1 没有实测加速，且部分设置的波动明显更大。延迟中位数汇总所有调用，加速比先按同轮方法与完整模型配对，再汇总全部种子；两个汇总量不必等于总体中位数直接相除。图表保留 IQR、p95 和逐种子结果，计时分位数不是置信区间。

七设置 × 两批量 × 五轮共 70 个轮次的前后 GPU 进程快照未见外部计算进程，全部计时窗口有效；服务器 CPU/I/O 仍共享，边界快照也不是连续性能监控。[完整延迟统计](../../results/vitl-and-latency-v1/latency_summary.json)／[准确率—延迟图](../../results/vitl-and-latency-v1/latency_accuracy.png)

## 从预检延伸出的数值实验

在线 GPU 排序与原排序在相同批量的 16 项预检中，选择、特征及得分完全一致。但缓存评估与在线批量形状不同时，FP16 路径出现小数值差异，部分临界 token 次序改变。因此，对七个设置、两个批量补做全部验证图片和未见组合的分类复查，使用相同权重、文本及三个种子，不重训。

某些方法／种子的选集变化比例最高为 17.25%，每例最多替换两个 token；比例按图片／任务案例计算，重复任务和种子不是独立图片。选择改变没有等比例变成预测错误：任一单方法／种子的加权预测分歧最高为 0.09804%。

对三种子平均的“条件化减图像版”主效应，在线批量相对原缓存结果的最大绝对变化为：

- **准确率：0.0163399 个百分点**，Flowers B/16、49-token、batch 32，从 +0.228758 变为 +0.245098 个百分点。
- **分类间隔：0.0000282144**，Pets B/16、49-token、batch 32，从 −0.000919076 变为 −0.000890862。

本次变化较小，但不是零影响，也不证明所有数值设置都稳定。诊断保留普通 95% 配对图片区间，与原预算校正的主分析分开。现有证据与排序边界敏感相容，未单独识别 FP16、具体 kernel 或排序分数间隙的因果贡献。[数值图表](../../results/vitl-and-latency-v1/numerical_sensitivity.png)／[完整统计](../../results/vitl-and-latency-v1/numerical_sensitivity.json)

## 执行、成本与保存

服务器目录为 `/data2/zhao.tong/experiments`。L/14 主实验在 physical GPU 3 完成十二个阶段；正式计时在 GPU 1，数值复查在 GPU 4，各七个设置全部完成。主实验来源版本为 `e64471f`，计时与数值实现为 `7d3e08a`；117 项相关服务器测试通过。运行来源与命令保存在执行记录，报告只需科研复现细节。

L/14 十二个阶段进程时间合计 4,402.50 秒（73.38 分钟）；其中使用 GPU 的阶段墙钟折合 1.213 小时，包含 CPU、加载、保存与同步。Pets／Flowers 分别为 0.7655／0.4475 小时。数值复查七个执行摘要合计 928.74 秒，单独记录，不属于推理延迟；计时运行、传输及归档没有加进这份主阶段成本。

统一成本表还覆盖已有 B/16 规模／预算实验及重用的教师来源，所列 GPU 阶段墙钟合计 2.153 小时。这是选定阶段的记录，不是项目累计总 GPU 用量、GPU kernel 利用时间或费用；共享前缀只计一次，Pets49 的 small/full 训练分别保留。[成本表与定义](../../results/vitl-and-latency-v1/experiment_costs.json)

小型统计、图表和执行摘要已纳入版本管理。五份大型档案合计约 3.2 GB，在本地保留并发布至 [GitHub Release](https://github.com/NathanTong0921/ViT-token-compression/releases/tag/vitl-and-latency-v1)，服务器原始运行文件继续保留。所有本地档案完整性与上传资产一致；另从 GitHub 重新下载模型与运行记录档案，核验全部 209 个成员和十二个 selector 的严格权重载入、最终步数及前向运行。这项恢复检查不等于重新跑一遍完整准确率评估。[恢复记录](../../results/vitl-and-latency-v1/recovery_verification.json)

## 对项目的推进与下一步

本轮总体是正面推进：跨模型 H2、Flowers 的分类收益、完整效率曲线和数值检查共同补足了 proposal 的主要验证。与此同时，Pets L/14 的负间隔差和 batch 1 的无加速结果限定了可支持的主张。可以围绕“任务几何关联较稳定、分类收益有条件、实际速度依赖运行批量”组织报告。

下一步冻结最终评估方案，使用预留测试图片及测试类别组合确认核心结论；报告骨架、主结果图表、PPT 和视频同步推进。无需因为未获得普遍领先而先扩成新的模型搜索。
